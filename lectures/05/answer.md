### 1. コンパクションとセッションをまたぐメモリの違い
* **コンパクション（ループの中の履歴の圧縮）**
  * 1つのセッション（コンテキストの中）で機能し、古い履歴を要約して詰める仕組みです（第3回・PDF p.39、p.65）。
* **セッションをまたぐメモリ（外の保存先）**
  * セッションを越えて情報を引き継ぐためのものであり、メモリツールや自動メモリを使ってファイル等に書き出し、次回のコンテキストに読み戻します（第3回・PDF p.39）。

---

### 2. 日々のメモはすべて長期メモリに入りますか
* **すべては入りません。**
  * 例えばOpenClawの例では、日々のメモ（`memory/日付.md`）の中から、毎晩の見直し（dreaming）によって「重複を除いて候補を並べる」「何度も出てくるテーマを探す」といった処理が行われます（第3回・PDF p.40）。
  * その結果、基準を超えたものだけが `MEMORY.md`（長期メモリ）に残され、一度きりの調べものは日々のメモに残るだけで長期メモリが膨らまない仕組みになっています（第3回・PDF p.40）。

**改良の回答（実出力）**

第3回の講義資料によると、コンパクションとセッションをまたぐメモリ（長期メモリ）は、それぞれ以下のように異なります。

* **コンパクション（履歴の要約）**
  * **範囲**：コンテキストの中（同じセッション内）で機能します（第3回・PDF p.39、p.65）。
  * **仕組み**：古い履歴を要約に置き換えることで、コンテキストの上限による情報の脱落を防ぎます（第3回・PDF p.38、p.39）。

* **セッションをまたぐメモリ（長期メモリ）**
  * **範囲**：コンテキストの外の保存先（ファイルやデータベースなど）に保存され、セッションをまたいで引き継がれます（第3回・PDF p.13、p.39）。
  * **仕組み**：エージェントが必要に応じて書き出し、次回の会話や新しいコンテキストの最初に読み戻します（第3回・PDF p.13、p.39）。

したがって、一度きりの調べものなどは日々のメモに残るだけであり、**すべてが長期メモリに入るわけではありません**（第3回・PDF p.40）。

## 宿題

- 取り組んだレベル：**実装**。
- 選んだ理由：1ページ1チャンクでは説明が隣ページに続くと根拠が欠ける可能性がある。既存の本文・DBを利用し、取得する範囲だけを変えた影響を確かめたかった。

### やったこと

- `app/retrieval.py`：公式最新版を読んだうえで、通常の`search()`を残し、`add_neighbor_pages()`と`search_with_neighbors()`を追加した。検索ヒットを元の順位で先に返し、その後に前・次ページを追加する。
- ページの照合と重複除去は`(document_id, page)`で行う。同じ資料のPDFページ番号±1だけを取得し、資料境界や欠番を飛び越えない。同一資料の章境界はまたぐ。
- 元の検索ヒットのdistance・本文・資料名・資料ID・章・ページタイトル・ページID・PDFページ番号を保持する。追加ページの引用情報も保持し、追加ページに検索距離を捏造しない。
- `app/tools.py`：前後ページ取得ツールを追加。通常RAGのツールも残した。
- `app/agent.py`：`--neighbors`を追加。同じ`search_materials`というツール名で実装だけを差し替え、通常起動では元の検索を使う。MCP・Tree・Graph・全文投入と排他選択にした。Tree/Graphの取得アルゴリズムは変更していない。
- 既存の用語検索・講義概要・クイズ・保存ツールと`DeferredToolRequests`、`resolve_approvals`を維持。`save_learning_log`は通常・改良の両方で`requires_approval=True`を維持した。MCPは独立した指示を使い、公開していないRAGツールを要求しない。
- SDKの再試行回数を`attempts=1`に設定。通常/改良RAGの埋め込みで429が返った場合はモデルにエラーを返して再検索させず、処理全体を停止する。

利用方法（APIを呼ぶため、比較済み結果の閲覧だけなら再実行不要）：

```powershell
uv run python -m app.agent --trace "質問"
uv run python -m app.agent --neighbors --trace "質問"
```

APIなしの登録確認は両コマンドに`--list-tools`を使用する。

### PRにDay5以外の差分が含まれる理由

forkのmainは古いMCP版で、公式mainとは分岐していた。そのため公式最新版を通常マージすると、Day4の採点コード・ラベル付けUI・教材、Day2の講師参考結果、Day1/3の教材修正、用語集更新、MCP教材の第6回への移動、README、依存関係の更新も差分に含まれる。
これらは公式履歴の取り込みによるもので、提出済み`lec04`やPR #4の変更ではない。forkのmainにない公式Day4の`answer.md`は空欄の公式テンプレートとして追加されている。
公式Day1教材の行末空白1か所のみ、差分チェックを通すため内容を変えず整えた。既存Day1〜Day3の解答・提出結果はorigin/mainに対して不変である。
